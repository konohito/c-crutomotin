# 利用者・測定の削除と、控えからの復元

## なぜ控えを残すのか

2026/09/16 に、台帳の誤記で持ち主が分からなくなった測定を「特定不明」と判断して削除した。
その後で山下芳代様のものだと判明し、控えから復元することになった。

**「特定不明」と判断した時点では本当に分からなくても、あとから分かることがある。**
そのため、画面からの削除は必ず控えを取ってから行う。控えを取らずに消す経路は作らない。

---

## 削除の流れ（`src/lib/deletion.js`）

1. **消えるもの一式を `deletedRecords` に書き出す**（＝控え）
2. **控えが書けたことを確かめる**
3. **本体を消す**
4. **誰がいつ何件消したかを `deletionLogs` に残す**（中身は書かない）

**①が失敗したら②で止まり、本体は消えない。**

### 利用者を削除すると、一緒に消えるもの

| 対象 | 扱い |
| --- | --- |
| `users/{userId}` | 削除 |
| `measurements`（その方のもの全部） | 削除 |
| `techo/{userId}` と `techo/{userId}/logs` | 削除 |
| `portalUsers`（電子手帳のログイン） | 削除 |
| `walkins`（当日受付の用紙） | **消さない。**紐づけだけ外して「取り込み待ち」に戻す |

用紙を消さないのは、**用紙は別の方のものである可能性が残る**ため。

### 測定 1 件だけを削除

`measurements/{利用者ID}_{測定日}` を削除し、`users/{userId}.measKeys` からも外す。利用者は残る。

---

## 控えの置き場

### `deletedRecords/{backupId}`

消した中身がそのまま入っている。

```
{
  kind: 'user' | 'measurement',
  at, by, byName, reason,
  userId, userName, ward, muniName,
  user:        { ... },        // kind='user' のとき
  measurements: [ { _id, ... } ],
  techo, techoLogs, portalUsers, walkins,
  backupId, savedAt
}
```

**Firestore ルールで、職員からも読めないようにしてある**（`allow read: if false`）。
画面には出ないので「消したのに残っている」ようには見えない。
**書いたあとの書き換え・削除もできない**（`allow update, delete: if false`）。

### `deletionLogs/{logId}`

**誰がいつ何を消したか。中身（測定値など）は入っていない。**
職員は読めるが、書き換え・削除はできない。

```
{ kind, by, byName, reason, userId, userName, ward, muniName,
  measurementCount, years, pastYears, walkinDetached, backupId, at }
```

## 控えから復元する手順

**復元は管理者が Admin SDK で行う**（画面からは読めないため）。

### 1. 控えを探す

```bash
TOKEN=$(gcloud auth application-default print-access-token)
P=cruto-motion
# 操作ログから、消した相手と backupId を探す（職員でも読める）
curl -s -H "Authorization: Bearer $TOKEN" -H "x-goog-user-project: $P" \
  "https://firestore.googleapis.com/v1/projects/$P/databases/(default)/documents/deletionLogs?pageSize=300"
```

### 2. 控えの中身を取り出す

`deletedRecords` はルールで読めないが、**Admin SDK（サービスアカウント）や
`gcloud` の資格情報による REST 呼び出しはルールを通らない**ため読める。

```bash
BACKUP_ID=user-24910-xxxxx
curl -s -H "Authorization: Bearer $TOKEN" -H "x-goog-user-project: $P" \
  "https://firestore.googleapis.com/v1/projects/$P/databases/(default)/documents/deletedRecords/$BACKUP_ID" \
  > /tmp/backup.json
```

### 3. 書き戻す

控えの `user` を `users/{userId}` に、`measurements[]` をそれぞれ
`measurements/{_id}` に書き戻す。`techo` / `portalUsers` も同様。

**書き戻す前に必ず確認すること**

- **同じ ID の利用者が、別人として作り直されていないか**（作り直されていたら ID をどうするか決める）
- **同じ測定キー（`{利用者ID}_{測定日}`）が既に使われていないか**
- **書き戻したあと、全項目が控えと一致するか**を項目単位で突き合わせる

`walkins` は削除していないので、書き戻す必要はない。必要なら紐づけを付け直す。

### 4. 復元したことを残す

`deletionLogs` に `kind: 'restore'` で 1 件足しておく（元の `backupId` を添える）。

## 画面のどこから操作するか

| 操作 | 場所 | 誤操作を防ぐしくみ |
| --- | --- | --- |
| 測定 1 件を削除 | 測定値の編集画面のいちばん下 | 「この測定を削除する…」を押して開かないと出ない。保存ボタンから離してある |
| 利用者を削除 | 個人ページのいちばん下 | 閉じた状態。開く → 何が消えるか読む → **氏名をそのとおり入力** → 削除 |
| まとめて削除 | 利用者台帳の「まとめて削除」 | 閉じた状態。開く → 選ぶ → **何が消えるか一覧で確認** → **「N名削除」と入力** → 削除 |

**利用者台帳の一覧そのものには手を入れていない**（並びも列も従来どおり）。
チェックボックスはパネルの中だけに置いてある。表に選択列を足すと、
日常の閲覧のたびに削除が目に入るため。

**まとめて削除は、1 人失敗しても残りは続ける。**失敗した方は画面に名前が出る。

## 権限について

**現在、職員の権限に区分はない。** `staff/{uid}` には `email` / `name` / `addedAt` しか無く、
管理者とそれ以外を分ける項目が存在しない（2026/09/18 時点で職員 5 名）。

そのため、**承認済みの職員であれば誰でも削除できる**。これは、
**職員が既に測定値の編集・統合・無効化といった取り返しのつきにくい操作を行える**のと同じ扱い。

区分を設けたい場合は、`staff/{uid}` に `admin: true` を足し、
`firestore.rules` の `users` / `measurements` の `allow delete` を
`isStaff() && get(/databases/$(database)/documents/staff/$(request.auth.uid)).data.admin == true`
に変えれば、管理者のみに絞れる。**誰を管理者にするかを決める必要があるため、現時点では入れていない。**
