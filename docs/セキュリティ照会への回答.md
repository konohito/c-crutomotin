## 1. ご照会のPHPの脆弱性（CVE-2026-109618 / CVE-2026-109619「PHP2Shell」）について

### 結論：当社アプリは影響を受けません。

**理由は、PHPを使用していないためです。**

Cruto Motion は、プログラムを動かすサーバーを自社で持たない構成（クラウドのマネージドサービス利用）で作られています。

| ご照会の前提 | 当社の実態 |
|---|---|
| PHP 8.2.35 より前など、PHPのバージョン | **PHPを1行も使用していません** |
| Webサーバー（Apache / nginx）の設定 | **自社では保有していません**（Google社の基盤が提供） |
| サーバーOSへの修正プログラムの適用 | **当社の作業対象外**（Google社が実施） |

当社が運用する全10アプリケーションを機械的に全文検索し、PHPファイル（`.php`）が**1件も存在しない**ことを確認済みです。

また「影響を受けるシステム」に挙げられた PHP 5.4 以降という範囲についても、そもそもPHPを導入していないため該当しません。

**あわせて申し添えます。** 今回のような「サーバーのソフトウェアに脆弱性が見つかり、各事業者が急いで修正プログラムを当てる」という対応が、当社の構成では**原則として発生しません**。サーバーOS・Webサーバー・言語処理系の保守はすべてGoogle社が担い、当社は利用する側であるためです。これは今回に限らず、今後の同種の脆弱性についても同様です。

## 2. 個人情報の取り扱いとセキュリティについて

ご心配をいただいた点について、構成と対策をご説明します。

### (1) データはどこに保管されているか

**日本国内（東京）です。**

| 保管先 | 場所 |
|---|---|
| 利用者情報・測定記録のデータベース | **東京**（asia-northeast1） |
| 記録用紙の画像 | **東京**（asia-northeast1） |
| プログラムの実行環境 | **東京**（asia-northeast1） |

Google Cloud（Google社のクラウドサービス）を利用しており、上記は設定値を実機で確認したものです。

### (2) 誰がデータを見られるのか

**二重の関門を設けています。**

1. **ログイン（ID・パスワード）** … Google社の認証サービスを利用
2. **当社管理者による職員登録** … ログインできても、管理者が職員として登録していない限り、画面には「閲覧権限がありません」と表示され、**データは1件も表示されません**

2段目を設けている理由は、「ログインできること」と「データが見られること」を切り離すためです。仮に第三者が何らかの方法でログイン用のアカウントを作成できたとしても、職員登録がなければデータには到達できません。

- **パスワードなしで入れる画面・体験版の入口は存在しません**（実コードで確認済み）
- **全アプリで共通の初期パスワード等は使用していません**。利用者用のパスワードは発行のたびに自動生成し、発行画面に一度だけ表示して保存しません

### (3) 通信と保存の暗号化

- **通信** … すべて暗号化通信（HTTPS）です。暗号化なしの通信はできない仕様です
- **保存時** … Google Cloud の標準機能により、ディスク上で暗号化されています

### (4) どのような情報を扱っているか

| 扱っている | 扱っていない |
|---|---|
| 氏名・ふりがな・生年月日・性別 | **住所（番地）** |
| 市町村・行政区 | **被保険者番号・保険証番号** |
| 要介護度・電話番号 | **マイナンバー** |
| 体力測定値（握力・歩行・バランス等） | **銀行口座・決済情報** |
| 基本チェックリストの回答 | |

対象は**約430名**です。事業の実施に必要な範囲に限って収集しており、住所の番地や保険証番号は保持していません。

### (5) 誤って消したときに戻せるか

**戻せます。**

記録を削除する際は、**消す前に必ず全内容を控えに書き出し、控えが書けなかった場合は削除そのものを実行しない**仕組みにしています。

この控えは、**職員が読むことも、書き換えることも、消すこともできません**（システムの権限設定で禁止しています）。復元は当社の管理者のみが行えます。

実際に2026年9月16日、職員の操作ミスで測定記録1件が削除された際、この控えから完全に復元しています。そのうえで、同じ事故が起きないよう手順を見直しました。

### (6) 操作の記録

**取り返しのつかない操作には、書き換えられない記録を残しています。**

- 記録の削除 … 誰が・いつ・何を・何件 を記録
- 利用者情報の統合（同一人物の名寄せ） … 同様に記録

これらの記録は、職員が後から書き換えたり消したりできません。

### (7) 外部への情報提供

**第三者への提供は行っていません。**

情報が当社の管理外に出る経路は、Google Cloud の2つの機能（記録用紙の文字読み取り）のみで、いずれもGoogle社との利用契約に基づく処理の委託です。広告・分析サービス等への送信は一切ありません。

**正直に申し上げるべき点が1つあります。** 記録用紙の文字読み取りに使う機能のうち1つは、**Google社が日本国内の拠点を提供していないため、米国の拠点で処理されます**（氏名が記載された用紙の画像が、読み取りの瞬間だけ米国を経由します）。

この点については以下を確認しています。

- Google社の公式仕様で、**読み取り処理に送ったデータは保存されず、AIの学習にも使用されない**と明記されています
- もう1つの読み取り機能は、当社の判断で**東京の拠点に変更済み**です（当初は地域指定なしでした）。変更を元に戻せないよう、自動検査で固定しています
- 国外処理が問題となる場合、**シンガポールなどアジア圏の拠点へ切り替えることが可能**です（ただしGoogle社が日本拠点を提供していないため、完全な国内処理は現時点では選択できません）

### (8) プログラムの公開範囲

Webサイトとして配信しているのは、**ブラウザの表示に必要なファイルだけ**です。プログラムの元のコード・設定ファイル・セキュリティ設定・社内文書は配信対象に含めていません。

### (9) 本番環境への反映の管理

- 自動検査（14種類）に合格しない変更は、本番環境に反映されない仕組みです
- 反映作業に使う認証情報は、**有効期限のない鍵を保持しない方式**を採用しています

## 3. 今後強化する予定の事項

ご照会を機に点検し、以下を強化予定としてお示しします。**現時点で未実施である点を含めて記載しています。**

| 項目 | 現状 | 予定 |
|---|---|---|
| ログインの多要素認証（パスワード＋スマートフォン等） | 未導入 | 導入予定 |
| 閲覧の記録（誰がどの方の情報を見たか） | 削除・統合のみ記録。閲覧は未記録 | 記録する仕組みを整備中 |
| 職員の権限区分（閲覧のみ／編集可 の区別） | 区分なし（登録職員は同一権限） | 区分を設ける予定 |
| 記録用紙の画像へのアクセス制限 | **対応済み（2026年10月22日）** | 職員登録済みの方のみ参照・削除できるよう変更しました |
| 文字読み取り機能の呼び出し制限 | **対応済み（2026年10月22日）** | 職員登録済みの方のログインを必須としました |
| データベースの定期バックアップ | 削除時の控えは実装済み | 時点復旧の設定を整備 |

## 4. 想定されるご質問への回答

**Q. ご照会を受けて、実際に何か直したのですか。**
A. はい。点検の結果2件を同日に修正しました。①記録用紙の画像が、ログイン済みであれば参照できる状態だったため、職員登録済みの方のみに限定しました。②文字読み取り機能の呼び出しに、職員のログインを必須としました。いずれも、データベース側で既に行っていた制限と条件をそろえたものです。今後同じ緩みが生じないよう、自動検査（25項目）を追加しています。

**Q. 情報が漏れた場合、どうやって気づけるのですか。**
A. 削除・統合といった重大な操作は書き換えられない記録に残ります。一方、閲覧の記録は現在未整備であり、上記3の通り整備を進めます。

**Q. 事業者が倒産した場合、データはどうなりますか。**
A. データはGoogle Cloud上の貴庁向け領域に保管されており、当社が消失させることはできません。移管・返却の手順はご相談のうえ定めさせていただきます。

**Q. 従業員が勝手に持ち出せるのではないですか。**
A. 現在、職員として登録された者は閲覧・編集が可能です。権限区分と閲覧記録は上記3の通り整備予定です。持ち出しを技術的に完全に防ぐことはできないため、**就業規則および秘密保持義務による管理**と併用しています。

**Q. なぜPHPを使っていないと言い切れるのですか。**
A. プログラムの全ファイルを機械的に検索し、PHPのファイルが0件であることを確認しています。ご要望があれば、使用している技術の一覧をお示しします。
