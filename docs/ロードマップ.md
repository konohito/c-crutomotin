# 将来ロードマップ（要望メモ）

運用者からの将来構想。実装時はこのメモを起点に要件を詰める。

## 1. motion で登録した予定 → サーキットへの反映（2026/09/07 記録）

- motion（本システム）で登録した測定会などの予定を、サーキット（cruto-circuit。サーキットトレーニング店舗側のシステム）にも反映したい。
- 実装の当たり:
  - 両システムとも Firebase 構成のはず。motion 側の予定データ（測定会マスタ）を
    circuit 側が読める形にする（共有コレクション / エクスポート API / circuit 側での購読のいずれか）。
  - circuit 側リポジトリへのアクセスと、circuit 側の予定データモデルの確認が必要。
  - motion 側の予定は現状ほぼ静的（エンジンの DATES / EventModal）。同期対象にするなら
    まず motion 側で予定を Firestore に持つ形へ移す。

## 2. 該当スタッフへの LINE WORKS Bot 通知（同上）

- 予定の登録・変更時に、担当スタッフへ LINE WORKS の Bot で通知が飛ぶようにしたい。
- 実装の当たり:
  - LINE WORKS Developer Console で Bot を登録し、Server API（Service Account + JWT →
    アクセストークン）で Cloud Functions から送信する。
  - 必要な準備: Bot の作成（管理者権限）、クライアント ID/Secret・Service Account の発行、
    スタッフ ⇔ LINE WORKS アカウントの紐付けマスタ（staff コレクションに userId を持たせる等）。
  - まずは「予定リマインド」のような一方向通知から始めるのが安全。
